# 接线方式

本文按当前固件和项目安全约束整理。由于现场光耦型号、开发板引脚排布和主板接口尚未在仓库中记录，以下内容定义的是**信号连接关系和检查要求**，不是某一块开发板的完整 PCB 原理图。

## 总体原则

```text
电脑主板 PLED ──[隔离输入]──> ESP32-C3 GPIO0
ESP32-C3 GPIO1 ──[隔离输出]──> 电脑主板 PWR_SW
ESP32-C3 3V3/GND ────────────> 传感器和本侧光耦电路
```

ESP32-C3 一侧和电脑主板一侧必须通过光耦或等效隔离器件连接。ESP32 GPIO 不得直接接到电脑主板的 `PLED`、`PWR_SW`、5 V、12 V 或其他未知电压信号。

## 信号分配

| ESP32 信号 | 固件用途 | 连接对象 | 方向 |
| --- | --- | --- | --- |
| GPIO0 | PLED 状态采样 | PLED 光耦隔离输出 | 输入 |
| GPIO1 | 电源键短按控制 | PWR_SW 光耦隔离输出 | 输出 |
| 3V3 | 本侧传感器/光耦逻辑供电 | 仅连接允许 3.3 V 的本侧电路 | 电源 |
| GND | ESP32 本侧公共地 | ESP32、传感器和本侧逻辑电路 | 地 |
| I2C SDA/SCL | AHT25 温湿度 | AHT25 模块 | 双向 |

GPIO0 和 GPIO1 的具体物理排针位置取决于使用的 ESP32-C3 开发板，应以开发板丝印和原理图为准，不能只根据扩展板颜色判断。

## GPIO0：PLED 状态输入

### 推荐信号路径

```text
电脑主板 PLED+/-
        │
        └──> 光耦 LED 输入侧
              （串联限流电阻，按光耦和主板电压计算）

ESP32 3V3 ──> GPIO0 本侧上拉/光耦输出侧
ESP32 GPIO0 <── 光耦晶体管输出
ESP32 GND ──> 本侧光耦发射极/逻辑地
```

固件已对 GPIO0 配置内部上拉，并读取光耦输出电平。典型开集电极/开路输出连接为：

- 光耦输出集电极接 GPIO0。
- 光耦输出发射极接 ESP32 GND。
- GPIO0 由上拉保持高电平。
- 光耦导通时将 GPIO0 拉低。

在这个典型接法下，当前软件约定为：

| GPIO0 本地状态 | 设备上报值 | 页面显示 |
| --- | --- | --- |
| 稳定低电平 | `low` | 灯亮 |
| 稳定高电平 | `high` | 灯灭 |
| 采样窗口内发生足够变化 | `blinking` | 灯闪烁 |

注意：`low`/`high` 是 GPIO 电平，不是云端推断出的物理灯状态。若现场光耦输入极性或输出级接法相反，应先用万用表和串口/本地页面确认实际电平，再调整接线或设备端极性解释。不要只修改云端中文映射掩盖硬件极性问题。

### PLED 输入安全要求

- 必须有串联限流电阻，阻值按光耦 LED 额定电流、主板 PLED 电压和功耗计算。
- 不能把主板 PLED 电压直接送入 ESP32 GPIO0。
- 确认光耦输入侧不会影响主板原有 PLED 的正常亮度。
- 光耦输出侧只能使用 ESP32 允许的电平；GPIO0 上电默认状态和启动绑带功能必须纳入检查。
- 上电、复位和 Wi-Fi 重连期间应确认 GPIO0 不会产生危险输出；GPIO0 只作为输入。

## GPIO1：电脑电源键输出

### 推荐信号路径

```text
ESP32 GPIO1 ──> 限流电阻 ──> 输出光耦 LED 输入侧 ──> ESP32 GND

电脑主板 PWR_SW 两个引脚 <── 光耦晶体管/继电器干接点输出
```

电源键通常是主板上的一个无源瞬时开关输入。光耦输出侧应模拟“短接 PWR_SW 两端”，而不是向主板输入 3.3 V 或 5 V：

- 光耦输出端的两个端子分别接主板 `PWR_SW+` 和 `PWR_SW-`。
- 保留原机箱电源按钮并联接入，便于现场人工操作和故障恢复。
- 不要把 ESP32 GND 接到主板 PWR_SW 任一端，优先保持隔离。
- 不要把 GPIO1 直接接主板 PWR_SW。

当前固件在空闲时将 GPIO1 置 LOW，执行时置 HIGH 约 300 ms 后恢复 LOW。因此驱动电路必须做到 GPIO1=LOW 时光耦 LED 截止、GPIO1=HIGH 时光耦 LED 导通。若实际光耦驱动级是低电平有效，必须调整驱动级或固件并重新验证，不能直接照接。

### GPIO1 输出安全要求

- GPIO1 输出侧必须有串联限流和合适的驱动能力；若光耦 LED 电流超过 GPIO 允许值，应增加三极管或 MOSFET 驱动级。
- GPIO1 启动输出默认低电平，外部驱动应有下拉或等效失效安全设计，避免复位/高阻阶段误导通。
- 光耦输出侧必须满足主板 PWR_SW 的电压、电流和绝缘要求。
- 用示波器或逻辑分析仪确认脉冲宽度约 300 ms，且上电/复位没有额外脉冲。
- 首次联机测试时，先断开主板 PWR_SW 输出侧，仅测试 ESP32 侧 LED/光耦动作；确认无误后再连接主板。
- 远程测试会真实触发电脑电源键，必须在现场确认电脑状态后进行。

## AHT25 接线

AHT25 使用 I2C：

```text
ESP32 3V3  ──> AHT25 VCC
ESP32 GND  ──> AHT25 GND
ESP32 SDA  ──> AHT25 SDA
ESP32 SCL  ──> AHT25 SCL
```

SDA 和 SCL 必须有适合 3.3 V 的上拉。若 AHT25 模块已经集成上拉，不要重复并联过多上拉电阻。AHT25 模块不得使用超过 ESP32 GPIO 允许范围的逻辑电平。

当前具体 SDA/SCL GPIO 没有在本文件中硬编码，应以 `environment_sensor.cpp` 和开发板原理图为准；修改引脚后必须同步更新固件配置和现场接线记录。

## 首次通电检查顺序

1. 不连接主板 PWR_SW 输出侧，只接 ESP32 本侧和隔离输入侧。
2. 用万用表确认 ESP32 3V3、GND 和各 GPIO 没有短路或过压。
3. 上电观察 GPIO1 不应产生电源键动作。
4. 用本地页面查看 GPIO0/PLED 状态，确认实际亮灭与“灯亮/灯灭”对应关系。
5. 让 PLED 处于稳定亮、稳定灭和闪烁状态，确认本地状态变化经过采样窗口后正确更新。
6. 单独测试 GPIO1 光耦输出侧的通断和约 300 ms 脉冲。
7. 断电后恢复原机箱 PWR_SW 接线，再进行一次现场确认的短按测试。
8. 最后才验证云端命令，检查设备回执和电脑实际反应。

## 必须现场确认的项目

- 光耦型号、CTR、隔离耐压和输入限流电阻。
- 主板 PLED 和 PWR_SW 接口的实际电压、电流及极性。
- GPIO0 光耦输出的有效电平是否为低电平。
- GPIO1 光耦输出是否为无源干接点，是否会在 ESP32 重启时误导通。
- 开发板 GPIO0/GPIO1 的启动复用、上拉和板载电路是否影响上述行为。
- ESP32、传感器和光耦本侧的 3.3 V 电源容量与地线质量。
