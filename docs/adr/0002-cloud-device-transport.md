# ADR 0002：设备与云端使用 HTTPS 轮询

- 状态：已接受
- 日期：2026-10-20

## 背景

首版需要在现有单台主机上提供安全且易维护的远程控制。用户明确优先考虑通信简单、安全和较低故障率。MQTT 会额外增加 Broker、凭据与 ACL、主题策略及独立服务的运维工作。

## 决策

设备主动通过 HTTPS 请求云端 API。在线时每 5 秒轮询一次，每 30 秒报告心跳；每次轮询最多领取一条命令。命令带唯一 ID 和过期时间，设备负责去重并回报执行结果。设备离线或命令过期时不排队、不重放。首版不使用 MQTT Broker，也不开放设备入站端口。

## 影响

- 只需维护一条设备通信协议，不需要 Broker 生命周期和 ACL 运维。
- 命令延迟大致受轮询间隔和网络/服务延迟影响。
- 必须明确设计并测试 API 认证、防重放、轮询负载、TLS 验证、凭据撤销和命令领取语义。
- HTTPS 轮询不能替代设备身份认证和授权。
